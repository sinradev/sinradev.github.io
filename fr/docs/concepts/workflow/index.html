Workflow

Sinra organise le travail en six étapes : Specify, Refine, Plan, Build, Verify, Learn. Ce n'est pas un processus à certifier, c'est l'ordre dans lequel un projet avance, et la structure de la barre latérale.

Qu’est-ce que le Workflow ?

Le Workflow est le fil conducteur de Sinra. Il découpe la vie d’une fonctionnalité en six étapes, toujours dans le même ordre :

ÉtapeQuestion poséeCe que vous manipulez
SpecifyQue doit permettre le produit ?Capabilities, specs, Spec Pipeline
RefineEst-ce assez clair pour s’engager ?File de refinement, séances d’estimation
PlanQue livre-t-on, et quand ?Releases, cycles, backlog, réunions de planning
BuildQui fait quoi maintenant ?Issues, cycle en cours, release en cours
VerifyEst-ce prêt à partir en production ?Tests, revues de phase
LearnQue change-t-on la prochaine fois ?Rétrospectives, post-mortems

Les noms d’étapes restent en anglais dans l’application, quelle que soit la langue de l’interface.

Les Étapes et les Objets

Sinra repose sur quatre objets : capabilities, issues, cycles et releases. Le Workflow ne les remplace pas, il les ordonne :

  • Les objets répondent à “quoi ?” : ce sur quoi vous travaillez.
  • Les étapes répondent à “quand ?” : ce qu’il convient de faire maintenant.

Une même capability traverse les six étapes. Elle est rédigée en Specify, estimée en Refine, placée dans une release en Plan, réalisée par ses issues en Build, testée en Verify, puis relue en Learn.

Le V-Model Sans le Jargon

Lues dans l’ordre, les six étapes dessinent un V :

Specify                         Learn
   Refine                   Verify
       Plan             
            Build

Les trois premières étapes descendent : on précise avant de produire. Build est le point bas. Les deux dernières remontent : on vérifie ce qui a été précisé, puis on en tire des leçons pour la spécification suivante.

C’est ce qui relie le V-Model et l’approche par cycles courts. Le V donne la rigueur (rien n’est construit sans spec, rien n’est livré sans vérification). Les cycles donnent le rythme : la boucle se répète à chaque release, pas une fois par projet.

Ce Que le Workflow N’Est Pas

  • Pas un processus imposé : aucune étape n’est bloquante. Une petite équipe peut passer de Specify à Build sans séance de refinement.
  • Pas une certification : il n’y a rien à apprendre avant de commencer. Les six mots sont dans la barre latérale.
  • Pas une cascade : plusieurs capabilities sont à des étapes différentes au même moment. Le Workflow décrit le parcours d’une fonctionnalité, pas le calendrier de l’équipe.

Dans l’Application

La barre latérale reprend ces six étapes dans sa section Workflow. Chaque étape regroupe les écrans utiles à ce moment du projet. La section Data, juste en dessous, donne accès aux listes complètes. Voir Navigation pour le détail des entrées.

Les événements de sync se placent naturellement sur ce parcours : la réunion de planning en Plan, la revue de phase en Verify, la rétrospective et le post-mortem en Learn.
